BoxBin web CRUD audit — 2026-11-18

Published core scope
- QR creation in both entry points supplies UUID IDs. Supabase supplies defaults
  for imported text IDs in qrcodes, shared_access and subscriptions.
- QR requestId is available for the template flow. Label reads paginate beyond
  Supabase's 1000-row limit. Write failures retain the form and show an error.
- Profile synchronization is an authenticated RPC that derives identity from
  Auth. It is idempotent and retains existing imported profile IDs and usernames.
- Sharing uses an authenticated, idempotent username lookup and grant RPC.
  Revocation confirms the deleted row. Canonical recipients can read shared
  inventory. Existing Firebase-era policies and ownership are preserved.
- Item image uploads use the canonical owner's folder plus UUID filenames.
  Storage policies permit upload/deletion within that namespace and deletion of
  older files owned by the same uploader. Service-owned imported files outside
  that namespace are not reassigned or deleted by this change.
- Chat deletion confirms a returned row. Subscription queries only treat active
  or trialing subscriptions as current.
- External API fallback points at the same DigitalOcean host used by mobile.

External and inherited limits
- API repository: carlosn422/BinventoryQRAPI, task/supabase (DigitalOcean).
  Export/template routes now verify ownership or granted read access, paginate
  inventory and handle imported profile IDs without invalid UUID casts.
  Service authentication derives ownership from the trusted copilot_owner RPC.
  Video status is owner-scoped; storage maintenance requires a trusted admin.
- Processing migrations 202611180006 and 202611180007 were rehearsed against
  production inside rollback transactions, then applied. Per-owner locking and
  request receipts make debit and result persistence atomic and idempotent.
  Existing conflicting token stores produce an error, not silent reconciliation.
- move-image-to-final and move-image-to-final-images were deployed. They require
  authentication and an owned Supabase storage path, copy to a unique item path,
  and retain the source for other extracted items. Web refuses to save an item
  when its image promotion fails. No external URL is fetched by these handlers.
- API image/video models are configurable with GEMINI_IMAGE_MODEL and
  GEMINI_VIDEO_MODEL; credentials come from the API runtime GEMINI_API_KEY.
  This is separate from Supabase Edge Function secrets used by web/mobile
  Copilot. Runtime availability must be verified; repository env is not proof
  of deployed configuration. No paid Gemini generation was exercised.
- Processing checks: 3 database/storage tests, 9 API unit/HTTP tests; mobile
  profile regression and TypeScript. Live smoke outcome is reported separately.
- Legacy owners differ from canonical Auth owners for some migrated accounts.
  No bulk owner remapping or removal of inherited broad policies was performed.
- Public QR reads/legacy QR update policies remain compatible with existing
  scanner clients; this is not a completed database-wide security audit.
